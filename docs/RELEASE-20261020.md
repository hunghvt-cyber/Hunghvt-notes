the Chia sẻ Note details collapsed. Load this listing only when expanded. Clear

## Remaining diagnosis

Content opens still use two catalog lease cycles; lists and all writes share the
same root. Retry improves eventual admission but increases requests. Next prioritize
avoiding duplicate/background requests and use existing sanitized operation durations
from actual traffic to distinguish network time from BUSY contention. Do not remove
ACL checks or use stale shared authorization as a shortcut. No new external service.

## Foreground priority and quieter recovery UI

User requested reducing background load to prioritize opening/saving, and simplifying
visible device-draft UI. Follow-up changes:

- One per-tab HTTP lane prioritizes queued writes, foreground reads, then optional
  background reads. It never aborts an already dispatched write. Retry waiting is
  outside the lane so it does not block another foreground action.
- Identical concurrent GETs within the same foreground/background context share a
  promise. This is in-flight coalescing only, not an authorization/content cache.
- Optional background refresh is skipped while hidden/offline or while foreground,
  editing/delivery or organization work is active. Background reads make a single
  attempt rather than start a two-minute retry chain. Periodic refresh is nonoverlapping
  and jittered at 60–70 seconds after each completed tick; background ticks do not add
  trailing full-refresh requests while another refresh runs.
- Shared links retain periodic/visibility authorization checks. During editing or
  foreground work, accessOnly reads validate live capability/scope/membership under
  one lease and return permission only, without reading immutable content. Foreground
  read/write ACL checks remain unchanged. Busy/network failures do not count as a
  successful authorization check or trigger a background retry storm.
- Stale open responses do not replace a newer editor choice. Background refresh does
  not repaint a dirty shared editor unless its permission changed to read-only.
- Normal status text is short: Đang lưu / Đã lưu / Chưa đồng bộ. The recovery panel no
  longer opens automatically; its button hides when empty. Existing draft records,
  frozen operations, export and conflict recovery are preserved. No draft deletion,
  storage migration or false cloud-save acknowledgement was introduced.

Validation performed: JavaScript syntax checks and diff review only. Browser selectors
